## Rulings made in this plan

- **A member's drop that needs a renumber:**
  - When the gap is too small and the mover can't change every card in the column (they can't `task.manage`), the drop goes to the server. It asks the mock to renumber the column with the new task `tasks.moveTo`, a new write that places the task and renumbers in one transaction.
  - The mock allows it under the same rules as a status change: a manager, or the assignee moving their own card.
  - That also removes the flicker, because the board waits for one write.
- **Import's files:**
  - Import clears the stored file bytes too, so the copy becomes true.
  - The copy also says plainly that an export carries no file contents: "Files aren't in the export, so attached files won't open after an import."
- **A person's first rate pricing their earlier time:** the ruling stands, and §4.4 says so. Time logged before a person's first rate uses that first rate, not 0. A changed rate never rewrites past cost.
- **Typing:** `onTyping` is wired in the project's Chat tab too, through the same shared client. Threads stay without it, since the indicator lives on the channel.

## Review Focus

1. **A member drops their own card where a renumber is needed.** It lands where dropped, with no 403 and no flicker. Test is in Task 1.
2. **Retyping a column to Done, or deleting a column into a Done one, with a timer running on one of its tasks.** The timer stops, and the task can then take new timers once reopened. Test is in Task 2.
3. **Archiving twice** (a double click, or two tabs). There is one history line and one `archivedAt`. Test is in Task 3.
4. **Projects fail to load in a public channel.** The composer area shows "Couldn't check who can post here. Try again." with Try again. Browser check is in Task 4.
5. **CSV with a name like `  =SUM(A1)` (leading spaces).** It is kept as text. Test is in Task 5.
