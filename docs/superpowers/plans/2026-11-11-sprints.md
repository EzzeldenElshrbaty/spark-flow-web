# Sprints Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Agile projects can create, plan, start and complete sprints, with a Sprints view in the Tasks tab and
started/completed cards in the project chat.

**Architecture:** Pure sprint rules in `src/lib/sprints.ts`, shared by the mock and the sheets. A new `api.sprints`
group (mock `src/mocks/sprints.ts`, HTTP `src/lib/http.ts`) owns every write; each write is one `db.update` that also
logs history, audits, posts the chat card and publishes `projectChanged`. The UI is a new `pages/projects/sprints/`
folder (view, section, sheets) wired into `TasksTab`.

**Tech Stack:** React 19, TypeScript, TanStack Query, dnd-kit (already used by the board), Vitest (unit + browser).

**Spec:** `docs/superpowers/specs/2026-11-11-sprints-design.md`

**Worktree:** `Spark_Flow/.worktrees/sprints`, branch `feat/sprints` (dev 63af2d6 merged in), `node_modules` linked to
the main checkout's.

## Global Constraints

- Curly apostrophes (’) in every string a person reads; `src/copy.test.ts` fails on a straight one.
- Kit look on project pages: semantic tokens only, `Sheet` for every dialog, `MenuPanel` for every menu, one primary
  (red) button per view (the Tasks tab's New task stays it), no toasts, no spinners, light and dark, 390 px phone.
- Logical direction classes only (`ms-/me-/ps-/pe-/start-/end-`); `src/rtl.test.ts`.
- Dates through `lib/format.ts`; numbers `tabular-nums`.
- Components import hooks from `@/api/*`, never `@/mocks`.
- Each mock write is one `db.update`; `audit()` inside it; a new `Api` method is listed in `src/mocks/audit.test.ts`.
- After a mutation: every query invalidated (the query client does it), the sheet closes, `announce()` says what changed.
- No DB version change (the DB is v35 after voice messages).
- Refusal sentences exactly as spec §5's table.
- Gates before landing: `npx tsc -b`, `npx oxlint`, `npx vitest run < /dev/null`, `npm run test:ux`.

## Review Focus

1. **A task put into a closed sprint** (task sheet, an old tab, a stale drag): refused, "That sprint is closed. Pick a
   planned or running one." — the task keeps its sprint. Test in Task 2.
2. **Archived tasks inside a sprint:** they don't count toward "empty", totals or "N not done", and Complete leaves them
   where they are. Tests in Tasks 1 and 2.
3. **A project switched from agile to waterfall:** the Sprints view isn't offered (`?view=sprints` falls back to the
   board) and every sprint write is refused. Tests in Tasks 2 and 4.
4. **An active sprint past its end date:** the header says "Ended 2 days ago", Complete still works, and the Board
   still opens on it. Tests in Tasks 1 and 6.
5. **Completing into "a new sprint" when names are irregular** ("Sprint 9", "Hotfix", "Sprint 12b"): the new sprint is
   "Sprint 13" and its dates start the day after the closed one's end. Test in Tasks 1 and 2.

### Task 1: Sprint rules

**Files:**
- Create: `src/lib/sprints.ts`
- Test: `src/lib/sprints.test.ts`

**Interfaces:**
- Produces:
  - `nextSprintName(names: string[]): string`
  - `defaultSprintDates(sprints: Pick<Sprint, 'endDate'>[], now: Date): { startDate: string; endDate: string }` — the
    local start of the day after the latest `endDate` (or today when that's past or there's none), to the local end of
    the 14th day.
  - `type SprintForm = { name: string; goal: string; startDate: string; endDate: string }`
  - `sprintErrors(v: SprintForm): Partial<Record<'name' | 'goal' | 'endDate', string>>`
  - `sortSprints(sprints: Sprint[]): Sprint[]` — active, then planned by `startDate`, then closed by `endDate` newest
    first.
  - `sprintDays(sprint: Pick<Sprint, 'startDate' | 'endDate'>, now: Date): string` — "4 days left", "1 day left",
    "Ends today", "Ended 1 day ago", "Ended 2 days ago" (local days).
  - `sprintTotals(tasks: TaskView[], sprintId: string): { tasks: number; points: number; done: number; donePoints: number }`
    — leaves out archived tasks; done by `category === 'done'`.
